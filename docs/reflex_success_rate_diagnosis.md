# Reflex 成功率下降：执行逻辑核查与消融

后续更新：本文保留修复前的诊断事实。当前请求视觉与单帧固定 RoPE 的生产代码修复及
配对评测见 [单帧修复结果](reflex_single_frame_fix_results.md)。

检查日期：2026-11-08。目标仓库 `/data1/lin/Apaper2/openpi-copy`，参考代码
`/data1/lin/Reflex` 和 Reflex 论文。此报告区分确定的计算语义问题、运行时实现问题和
小样本行为证据；不把单元测试通过当作模型任务表现通过。

## 结论

当前代码实现了 VLA 的外层执行链，但完整流式路径没有保持此 OpenPI checkpoint
训练时的前缀计算、观测时序和上下文分布。最近 spatial 10 任务 × 3 次只有 1/30
成功，需要保留原始结果。最强的直接行为证据是额外一轮视觉延迟：在相同初始状态、
按推理序号固定噪声的三个任务上，标准前缀均成功，仅将图像换成上一轮请求图像后均失败。
历史帧和位置坐标也存在独立的分布变化，不能把全部下降归因于单一注意力 mask。

## 核查的 VLA 执行链

1. LIBERO 图像翻转、resize/pad、uint8 转换，状态拼接为位置 3 + 旋转向量 3 + 手指位置 2。
2. `LiberoInputs` 映射两个有效相机并补一个被 mask 的相机；使用 checkpoint 的归一化统计。
3. 提示词 tokenize、状态补维；图像按原 OpenPI 路径预处理并送入 SigLIP。
4. 标准 PI0.5 前缀为 `[图像; 语言]`，有效前缀 token 双向互相可见，位置由有效 mask 累加。
5. 前缀 KV 只在本次推理的十步 flow matching 之间复用；动作专家从噪声按 t=1…0.1 积分十步。
6. 对动作反归一化、取前七个坐标；LIBERO 原始动作本来就是 OSC delta，没有额外相对/绝对转换。
7. 模型输出十步、broker 保留前五步。每执行三步，在第四次取动作前提交下一次推理；
   当前 chunk 余下两步各执行一次，chunk 边界采用下一组前五步。
8. 异步 episode 结束时等待在途推理、reset 服务端视觉缓存。评测以 LIBERO `_check_success()`
   返回的 done 判断成功，220 是空间任务 rollout 上限，不是把环境 timeout 当成功。

在这些路径中，没有找到图像翻转重复、归一化统计选错、动作没有反归一化、预测十步全部执行、
动作 4/5 重复计入、suffix KV 跨去噪累积、图重放仍读旧输入或环形槽覆盖解码快照的证据。
这些检查不证明所有可能的并发/硬件情况都无错；本次 GPU 测试覆盖了实际使用的单客户端路径。

## 问题 1：视觉延迟叠加，当前没有有效的状态补偿

位置：`PI0Pytorch.sample_actions_streaming` 的 `background` 路径，
`ReflexActionChunkBroker.infer` 的 overlap 调度。

broker 本身在 chunk 剩两步时采样图像并启动下一组推理，所以标准异步路径已经有两步
lookahead。并发视觉路径随后不等当前图像编码，而是解码上一轮已完成的图像 KV。
推理请求间隔五个控制步，因此稳态下最新视觉与下一 chunk 开始执行之间约相差
`5 + 2 = 7` 个控制步。LIBERO 控制频率为 20 Hz，约为 **350 ms 仿真控制时间**，
不是 GPU kernel 时间或必须相同的墙钟时间。窗口中的更旧图像还会再早一个请求。

这改变了 action chunk 的时间对齐：模型把第一个动作当作紧接着观测之后的动作，
执行端却把它用在更晚的机器人/物体状态上。特别是接近、下降、夹爪闭合和提起阶段，
反复对旧图像做决策容易过冲和开合振荡。

当前 `pi05_libero` 设置 `pi05=True, discrete_state_input=False`。PI0.5 suffix 默认只接受
动作和时间，新增状态 MLP 的最后一层又是零初始化。因此虽然 broker 算了未来状态，
模型动作目前不依赖该状态。固定图像和噪声，把全部状态坐标加 5，开启零初始化分支前后，
输出差异均为 **0**。这是此 checkpoint/配置的事实，不应误称状态预测已经补偿延迟。
单独把 state 塞回离散提示词会改变训练输入，不是无需训练即可成立的修复。

参考 Reflex 源码的 `modeling_pi05.py` 增量 `prefill_forward` 在正常调用中使用
`concurrent_prefill(..., wait=True)`。因此目标仓库新增的这一轮滞后并非简单复制源代码
执行顺序；源码有并发工具不代表其原始调用路径同样使用旧视觉。

## 问题 2：固定语言 KV 不等价于原模型的双向视觉语言编码

位置：`reflex_cache.py:initialize/_prefill`，对照 `PI0Pytorch.embed_prefix/forward`。

原模型的语言 token 可以读取图像。第一层 KV 来自输入 embedding，但第二层及以上的语言
KV 依赖前层对图像的注意力输出。流式缓存却只对语言进行一次独立前向并永久固定，且让
当前图像读取这些语言 token，禁止语言读取图像。这是改变注意力图，不是只改变存储。

论文的 timestep-invariance 说明前缀不依赖 denoising timestep，所以同一个观测的 KV
可在十步去噪中复用；它不推出换了一幅图之后语言 KV 不变。论文对相同 partition mask、
相同固定输入窗口的缓存等价性，也不推出改 mask 后仍等价于原 checkpoint。

固定真实 LIBERO 初始观测与噪声，对照结果（前七个归一化动作坐标）：

| 改动 | 对标准路径的 RMSE | 最大绝对差 |
| --- | ---: | ---: |
| 仅交换物理存储顺序，保留各 token 的 RoPE 位置及全注意力 | 0.000724 | 0.002039 |
| 全注意力不变，但改为语言在前的新位置编号 | 0.051007 | 0.140336 |
| 保留原位置，仅禁止语言读取图像 | 0.081771 | 0.353706 |
| 语言在前的新位置 + 分区注意力 | 0.084930 | 0.262903 |

这些是单个真实输入的数值证据，不是数据集上的平均精度损失。BF16 GEMM/归约顺序使纯置换
也可能有小误差，不能承诺 bitwise 一致。保留位置、仅改变注意力时，value cache 第 0 层
差异为 0，第 17 层 RMSE 达 1.8002，符合视觉依赖通过层传播的分析。

单独使用分区注意力、每次从当前帧重建并重置位置，在选取的三个任务仍全部成功。
因此该问题是确定的 checkpoint 语义不兼容，尚不能单独解释全部 29 次失败。

## 问题 3：环形容量有限，但位置计数持续增长且语言坐标固定

位置：`StreamingPrefixCache._prefill` 中 `next_position += valid_token_count`，
`snapshot` 把累计 offset 传入动作专家。驱逐 KV 不重设这个计数。

每次观测有两个有效相机，共 512 个视觉 token。语言固定在开头，新的图像和动作 suffix
位置却持续远离语言。标准路径每个请求都在当前单帧上下文中重新编号，两个路径对语言、
图像、动作的相对 RoPE 距离因而不同。环形存储有界不能保证这些相对坐标保持不变。

固定同一幅真实图像、同一提示词、同一噪声，把窗口设为 1（完全排除多帧历史），仍得到：

| 第几次请求 | next_position | 动作相对首次 RMSE | 最大绝对差 |
| --- | ---: | ---: | ---: |
| 2 | 1044 | 0.02004 | 0.05379 |
| 10 | 5140 | 0.06012 | 0.16090 |
| 20 | 10260 | 0.07576 | 0.18408 |
| 45 | 23060 | 0.15028 | 0.47719 |

输入内容相同却仅因缓存计数变化而产生不同动作，是位置语义偏离的直接证据。
如果只用单帧，可在覆写旧帧前回到固定位置；对保留的多帧 KV，不能只减计数器，必须同时
正确重算/变换保留 key 的 RoPE 坐标及其上游依赖。简单取模不是已验证的修复。

## 问题 4：多帧历史没有对应的训练上下文

当前 checkpoint 的训练前缀是一帧的多相机观测，完整流式配置改成两条观测的视觉 token。
动作专家看到的有效视觉 token 数、旧/新画面分布、位置和注意力权重都变了，没有新增
明确的训练过的时间标识。即使不发生任何缓存读写错误，也不能当作无损优化。

没有视觉滞后的两帧配置在三个配对 episode 中成功 2 次；当前帧分区且每次重置成功 3 次。
这支持历史/位置带来额外影响，但该比较同时改变历史和位置增长，不能把它作为纯历史因果证明。

## 已运行的配对消融

每个模式使用 spatial 任务 0、6、8 的第一个初始状态，环境 seed 7，推理噪声固定为
`np.random.default_rng(42 + inference_index)`。各模式保持 broker 的 horizon 5 / overlap 2，
均使用融合投影与 CUDA Graph。闭环轨迹开始分歧后，比较的是各自轨迹，不能要求后续观测相同。

| 配置 | 任务 0 | 任务 6 | 任务 8 | 本组成功次数 |
| --- | --- | --- | --- | ---: |
| 标准前缀，当前图像 | 成功，95 步 | 成功，115 步 | 成功，120 步 | 3/3 |
| 分区前缀，当前帧，每次重置 | 成功，93 步 | 成功，126 步 | 成功，110 步 | 3/3 |
| 分区前缀，两帧历史，无额外视觉滞后 | 失败，220 步 | 成功，137 步 | 成功，124 步 | 2/3 |
| 标准前缀，仅换成上一轮请求的图像 | 失败，220 步 | 失败，220 步 | 失败，220 步 | 0/3 |
| 完整流式：两帧历史 + 上一轮图像 | 失败，220 步 | 成功，190 步 | 失败，220 步 | 1/3 |

这些小样本适合定位因果线索，不是完整 LIBERO 成功率，不应与旧 500 次结果直接做百分比对比。
相同环境/噪声下标准路径复测得到了相同成功步数，见 position_ablation 第二轮记录。

## 单帧位置配对验证（第二轮）

额外运行 12 个 episode。每个任务的四种模式都核对了图像和状态的 SHA-256，
确认初始输入完全相同；噪声仍按推理序号配对。

| 配置 | 任务 0 | 任务 6 | 任务 8 |
| --- | --- | --- | --- |
| 标准前缀、当前图像，重复对照 | 成功，95 步 | 成功，115 步 | 成功，120 步 |
| 标准前缀、上一轮图像，重复对照 | 失败，220 步 | 失败，220 步 | 失败，220 步 |
| 分区、单帧、无视觉滞后、位置累计 | 失败，220 步 | 成功，126 步 | 成功，138 步 |
| 分区、单帧、无视觉滞后、位置固定 | 成功，93 步 | 成功，126 步 | 成功，110 步 |

固定单帧位置只在诊断 wrapper 中把即将被完全替换的旧帧位置回到语言末尾；
保留语言 KV，不重新编码语言。这样可以排除重新计算语言的影响。
它与第一轮“每次重建单帧”在三个任务上的完整动作序列完全一致（最大绝对差 0）。
因此任务 0 的恢复和任务 8 的步数改善可以直接关联到这个单帧位置改动。
多帧位置仍需单独设计，不能把这一单帧诊断手段直接用于两帧环形缓存。

两轮合计 27 个 episode，无运行异常。没有启动新的 30/500 次完整基准。

## 其他发现及适用范围

- 夹爪最后命令沿用的逻辑存在，但 Panda 实际 `format_action` 是按 speed=0.01 累积开合目标。
  把负/正命令直接映射为全开/全闭 qpos 是目标极限近似，不能表示两步后的实际手指位置。
  当前状态分支为零，所以它不是本次动作失败的直接来源；若之后训练状态分支必须重新验证。
- OSC delta 累加仅预测命令目标，不预测接触、阻挡、控制误差或物体运动。
- 同步 LIBERO 分支没有像异步 broker 一样在每个 episode 结束时 reset 流式缓存；
  同步 + streaming 的未来使用存在跨 episode 泄漏风险。本轮 30 次全部用异步分支，不是本次主因。
- WebSocket 服务所有连接共享一个有状态 policy，不能让多个独立客户端同时共用视觉历史。
  本轮是一个评测客户端，没有该并发场景。
- `llm_ms` 在并发模式对应消费的视觉发布，bootstrap 在前两次消费中可能重复出现在计时记录里；
  episode 最后排空的视觉工作也不是独立推理记录。这影响阶段时延统计，不能据此推断成功率。
- CUDA Graph 和融合后的标准路径已固定噪声对照，并在本次配对任务成功，没有发现其导致当前
  大幅精度下降的直接证据。BF16 小数值误差仍存在，不应把所有模式叫做精确等价。
- 新状态 MLP 目前未接到训练配置/adapter 持久化流程。开启 server flag 只建立新的零输出分支。

## 修复方向及当前操作范围

本次增加诊断脚本和报告，保留生产推理实现及全部原始评测数据，避免检查过程中静默改写实验条件。

优先恢复与原 checkpoint 一致的执行流程：当前请求图像的 `[image; language]` 联合前缀，
本次请求重新计算前缀、只在十步去噪内复用 KV；保留融合、静态 suffix 和 CUDA Graph。
可以继续使用 broker 在两步动作执行期间计算完整下一次推理，但应单独验证这种 lookahead
带来的对齐误差，不再叠加额外一轮旧视觉。

如果需要保留论文式持续历史：必须针对分区注意力、固定语言、历史帧、相对位置和未来状态
条件训练/微调并重新评测。仅把窗口设小、位置取模、打开未训练的 MLP 或扩大 overlap，
不能同时解决这些问题。状态预测也不能修复旧图像中的物体/夹爪视觉错位。
